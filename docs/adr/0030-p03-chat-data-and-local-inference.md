## T02 scoped data contract and tests-first

1. Schema version 1 legacy records -> 2 normalized conversations, messages, migration history and change journal. Stable constrained ASCII IDs, role allowlist, bounded UTF-8 title/content, revision >=1, status allowlist, native timestamps. Composite FK enforces same-conversation parent, no cross-thread links; index history ordering. Retain all existing records exactly. Attachment bytes, artifact links and encrypted portable restore land in T08/T09/T12, not claimed here.
2. Before modifying existing v1, integrity and schema shape verified; create exclusive online backup to independent local snapshot path (not a substitute for offsite encrypted backups); verify snapshot integrity/version and source identity, transaction DDL and version update atomic. Unknown/future/corrupt schema denied; no implicit reset. New profile creates v2 atomically. Migration failure leaves v1 and existing backup intact. Version marker changes only in successful transaction; repeat open idempotent. Legacy snapshot restore allowed only to new staging and version compatibility explicitly checked.
3. New conversation/message insert validates IDs and size, performs BEGIN IMMEDIATE, writes content and journal event in same transaction, returns typed receipt only after commit. Duplicate/conflict returns stable error without overwriting. Read by ID/order from native storage; no WebView IPC for this T02 slice. No raw content in diagnostics. Data references may not cross thread. Reopen verifies committed bytes. T03 introduces typed IPC/UI separately.
4. Required Rust real SQLite tests: fresh v2 WAL/FULL/FK; actual v1 fixture migration preserves legacy text and versioned online backup; reopen no extra migration; unsupported version and corrupt bytes retained; conflict/invalid/cross-thread FK rejected with zero partial messages/journal; injected trigger abort verifies rollback and no acknowledgement; snapshot/restore into new fixture retains bytes, source untouched; existing P01 tests retained. CI read-only native startup must verify schema v2 and tables/foreign keys, zero fixture records. Run exact-head Windows release cargo tests + full Python regression + TS build, collect native proof. No mock-only DONE.
5. Threat model: SQL injection via parameterized statements; path traversal/symlinks and nonregular sidecars denied by existing vault (Windows reparse/ACL hardening tracked for later acceptance); oversized/untrusted content limited; no remote telemetry; fail closed on disk/full/busy, unknown schema and corruption. Backup staging uses private app-local path; encrypted offsite/restore and OS crash/reinstall remain T12/T13. No release claim.
6. Retry budget: diagnose distinct reproducible failures; one fix per identified cause then exact-head rerun, no blind endless retries. Native timing target existing 45s readiness bound, measured baseline not product SLA. Model fixture measures TTFT and generation counts; target established after actual measurement. No GPU assumption.
