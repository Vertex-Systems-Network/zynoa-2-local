## API and data contracts

Scoped API: `listReleasedChanges(channel, version?, cursor?)`, `getReleaseHistory(channel)`, `getChange(changeId)`, `listKnownIssues(module?, cursor?)`, `getModuleHistory(moduleId)`, `getPreferences()`, `setPreferences()`, `getAuditTimeline(scope, cursor?)`, `exportSanitizedHistory()`, `markReleaseRead(version, channel)`. Admin-only event ingress: `appendChangeEvent(eventEnvelope)` with durable idempotency and stream sequence; PR record validation via CI. Status is source-derived, not generated by model free text.

Data: `ChangeEvent`, `ChangeRecord`, `ReleaseManifest`, `ReleaseNoteEntry`, `ChangeFeedCache`, `UserReadState`, `HelpRevision`. SQLite migrations, stable error codes `CHG-E001` through `CHG-E010`, local encryption scopes where needed, input schema validation, status transition enforcement, and no public sensitive data.

## P00 developer-only GitHub CI incident delivery identity (2026-11-20)

`tools.github_issue_bridge` now requires run-ID/full-SHA GitHub Actions API readback of an actual failed `Governance v3.2` run (completed failure/same-repo allowed event) before an Issues write, and reconstructs a safe five-run history on the same verified **github-actions[bot]**-owned fingerprint issue. A repeated event causes no write, a different verified failure updates one issue, and failed delivery never claims success. The privileged listener uses trusted default-branch checkout only and is not active until protected P00 merge. These are **development incident engineering** contracts, not shipped M26 GUI/change-feed or published user telemetry. [Operations](../operations/P00_VERIFIED_CI_ISSUE_DELIVERY.md) · [ADR-0023](../adr/0023-ci-run-verified-sanitized-issue-delivery.md).

## P02 user interaction refinement

The local Change Center now distinguishes actual pending/connected/unavailable/browser transport states, with offline guidance that does not imply a signed release feed. Its no-result state is a real keyboard-operable reset action; reset restores search focus, Enter on a notice moves to its detail heading, and Back to notice list returns to the originating button. Unavailable explanations are keyboard reachable with associated descriptions while actions remain natively disabled. Responsive layout is based on available content width and the notice list does not hide items inside an additional scroll region. These are source implementation changes; native review remains pending.
