## API and data contracts

Scoped API: `listReleasedChanges(channel, version?, cursor?)`, `getReleaseHistory(channel)`, `getChange(changeId)`, `listKnownIssues(module?, cursor?)`, `getModuleHistory(moduleId)`, `getPreferences()`, `setPreferences()`, `getAuditTimeline(scope, cursor?)`, `exportSanitizedHistory()`, `markReleaseRead(version, channel)`. Admin-only event ingress: `appendChangeEvent(eventEnvelope)` with durable idempotency and stream sequence; PR record validation via CI. Status is source-derived, not generated by model free text.

Data: `ChangeEvent`, `ChangeRecord`, `ReleaseManifest`, `ReleaseNoteEntry`, `ChangeFeedCache`, `UserReadState`, `HelpRevision`. SQLite migrations, stable error codes `CHG-E001` through `CHG-E010`, local encryption scopes where needed, input schema validation, status transition enforcement, and no public sensitive data.

## Completion criteria

All 8 screens and 20 controls implemented (not mocked), 28 real screenshots captured with provenance and alt text, accessible navigation, offline caching, versions/release truth verified, docs/Wiki synchronized, reporting privacy tested, issues and rolled-back changes not shown as released, release notes identical between GitHub and desktop, and verified phase PR SHA. Prototype validator running does not mean product implemented.


## P00 developer-only GitHub CI incident delivery identity (2026-11-20)

`tools.github_issue_bridge` now requires run-ID/full-SHA GitHub Actions API readback of an actual failed `Governance v3.2` run (completed failure/same-repo allowed event) before an Issues write, and reconstructs a safe five-run history on the same verified **github-actions[bot]**-owned fingerprint issue. A repeated event causes no write, a different verified failure updates one issue, and failed delivery never claims success. The privileged listener uses trusted default-branch checkout only and is not active until protected P00 merge. These are **development incident engineering** contracts, not shipped M26 GUI/change-feed or published user telemetry.
