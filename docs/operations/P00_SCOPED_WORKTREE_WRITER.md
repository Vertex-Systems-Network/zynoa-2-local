# P00 real fd-scoped fixture write — detached disposable Git worktree only

**Module:** M22 · **Phase:** P00 · **Existing task:** P00-T20 IN_PROGRESS · **PR:** [#1](https://github.com/Vertex-Systems-Network/zynoa-2-local/pull/1) DRAFT.

## Capability boundary

Unlike the prior preview-only stager, `tools/scoped_worktree_fixture_writer.py` **actually creates exactly one new source file** on disk, but only under `tests/fixtures/*.py` in an **operator-constructed, detached `git worktree add --detach --no-checkout`** at a pinned, independently supplied Git SHA. This remains a narrow developer-bootstrap source capability; it cannot write normal user or source checkouts, overwrite existing files, apply arbitrary patch hunks, run a model, execute source, commit, push, merge, call GitHub or start P01. The operator has to pre-create the empty `tests/fixtures` parent directories in the isolated worktree and guarantee that the writer's account has exclusive control of the worktree and its ownership; the model receives **no root path, write grant, file descriptor or Git config**.

Operator-owned inputs are all distinct from model text: active P00 task ID, source checkout path, job root, trusted immutable Git SHA, SHA-256 authorization for exact candidate bytes, and three explicit opt-in flags (`enabled`, `operator_ack`, `write_grant`). The candidate is separately validated through existing `plan_python_syntax` and `WorkspaceScope.check` (one-level fixture Python only). A model may supply only a bounded, canonical UTF-8 draft and an independently checked `DRAFT_ONLY` proposal; it cannot authorize a write.

## Actual Linux filesystem transaction

The writer:
1. Denies non-POSIX/Windows and root (UID 0) runtimes and platforms without `dir_fd`/`O_NOFOLLOW`/`O_DIRECTORY` support.
2. Rejects a normal checkout `.git/` directory, any symlinked worktree/root, unexpected worktree naming/placement, overlaps with source repo, mismatched linked `.git` gitdir pointer or detached HEAD SHA. An actual trusted Git worktree, generated by the existing fixed `plan_detached_worktree`, is required; Git commands are **not invoked by the writer**.
3. Opens the worktree and `tests/fixtures` parents with directory file descriptors, `O_NOFOLLOW`, UID ownership validation and no group/world-writable directory rights. A path string is not trusted as an already-open file capability.
4. Creates unpredictable same-directory temporary inode `0600` with `O_CREAT|O_EXCL|O_NOFOLLOW`, writes bounded bytes, fsyncs and rechecks inode/size. `os.link(src, final, src_dir_fd=..., dst_dir_fd=..., follow_symlinks=False)` publishes the new path **without replacing an existing file, directory or symlink**. Verifies the published inode, reads bounded bytes via `O_NOFOLLOW`, checks SHA-256, removes temporary name, fsyncs directory.
5. Returns only phase/task/path, source commit, authorized candidate hash and file byte count; **no source content or secret host absolute path in receipt**. One new disposable worktree file is counted; trusted source checkout writes and GitHub writes remain zero.

A failure before publication cleans the temp name; failure during/after atomic publication requires trusted reconciliation before retry, **not a blind delete or success claim**. Single-owner host permission separation is essential: a malicious peer with the **same UID** controlling the target directory can still race fd checks or alter a file after verification. This is **not** an OS sandbox, transaction journal, arbitrary safe patch engine, durable authorization manager or security-attested runtime. An attacker with operator-host privileges could choose dangerous trusted inputs; model requests must never be allowed to set them.

## Two rejected alternatives and official reference sources — 2026-11-20

- Directly `Path.write_text` to a normal checkout: rejected due to overwrite, symlink/TOCTOU and lack of commit isolation.
- `os.replace` a model draft into a checkout: rejected because overwrite is implicit, failure reconciliation is unclear and arbitrary scopes are too broad.
- Chosen: separate detached target + non-root ownership + descriptor-relative no-follow open + no-overwrite link publication. Official Python 3.12 [`os.open`, `dir_fd`, `os.link`, `O_NOFOLLOW`](https://docs.python.org/3.12/library/os.html) and Linux [`linkat(2)`](https://man7.org/linux/man-pages/man2/linkat.2.html) describe platform support and name-resolution semantics. Linux [openat(2)](https://man7.org/linux/man-pages/man2/openat.2.html) describes why directory FDs are more robust against path races. Fixed Git worktree planning in [P00 Worktree Policy](P00_WORKTREE_POLICY.md) is an **execution plan only**, not an authorization to checkout untrusted code.

## Verification

```sh
python -m unittest tests.test_scoped_worktree_fixture_writer -v
python -m unittest tests.test_workspace_policy -v
python -m unittest discover -s tests -v
```

Linux CI **actually creates a brand-new private Git test repository**, commits an empty trusted commit, creates an independent detached no-checkout Git worktree and performs a *real on-disk fixture creation* in that disposable worktree; regression tests reject existing file, existing symlink, parent symlink, group-writable directory, forged source SHA, mismatched `.git` pointer, wrong task, malicious text, repeated source, missing grants and simulated publish failures. Windows CI must deny real fd-scoped writes and never runs an unsafe fallback. These tests **do not write to the actual user checkout**, install a user-host worker or contact Ollama. Source and real host need separately verified resource/credential isolation before any real AI-generated fixture is installed in an operator-owned worktree.

The next independent step is operator-hosted lease-guarded job creation, authenticated Ollama + rootless Docker code-execution checks, and a trusted broker that binds the **exact passing candidate digest** from an independently attested sandbox to this host-owned write grant. A disposable fixture write alone is **not** a tested model source patch/repair, not a CI-based GitHub write/PR proof, and not continuous autonomous development.
