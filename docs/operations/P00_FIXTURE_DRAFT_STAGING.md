# P00 Ephemeral Fixture Draft Preview — No Execution / No Source Writes

**Module:** M22 · **Phase:** P00 (active branch `phase/00-governance`) · **Existing [draft PR #1](https://github.com/Vertex-Systems-Network/zynoa-2-local/pull/1)**.

**Purpose:** A safe *pre-execution* step for P00-T20. Given a model's already validated `DRAFT_ONLY` plan and candidate UTF-8 content, the trusted host may preview small fixture files in an automatically deleted temporary directory and get deterministic hashed receipts. This is NOT an OS sandbox, executable coding worker, source-file patch, unattended test/repair loop or deployment. All privileged actions remain disabled.

## Pre-development and source review (2026-11-18)

The previous [P00 local model planner](P00_LOCAL_MODEL_PLANNING.md) can propose bounded paths, but cannot change files. Before any future sandboxed edit/test step, an independent host needs a staging/review contract that rejects untrusted scope escalation, file path traversal, dangerous content and oversized payloads without exposing user files or GitHub credentials.

Relevant official Python documentation:
- [Python 3.12 tempfile](https://docs.python.org/3.12/library/tempfile.html): `TemporaryDirectory` is a context manager and deletes its directory and contents when leaving the context, subject to normal OS cleanup semantics.
- [Python 3.12 ast](https://docs.python.org/3.12/library/ast.html): AST parsing is **not** safe as a privileged host isolation boundary; sufficiently complex untrusted input can cause resource exhaustion or crash. For this reason the stager does **not** parse, import, compile or execute proposed Python code. Real syntax tests must be performed in an independently constrained process.
- [Python 3.12 os.open](https://docs.python.org/3.12/library/os.html#os.open): staging uses exclusive creation and no-follow flag where available; this is defense in depth, not a substitute for host OS file-handle/mount isolation.

## Implemented code and trust boundaries

`tools/fixture_draft_stager.py` exports:

```python
preview_fixture_drafts(
    plan: dict,
    candidates: dict[str, str],
    scope: WorkspaceScope,
    *,
    expected_task_id: str,  # TRUSTED HOST INPUT: never take from model JSON
) -> dict
```

1. **Trusted identity:** `scope` is generated by the trusted host and locked to active P00/branch. `expected_task_id` comes from trusted orchestration; a model cannot authenticate itself by claiming its own ID.
2. **Independent model plan validation:** Re-run `validate_model_plan(plan, expected_task_id, scope)` and check the scope for each path. Reject mismatched phase, task, branch, symlink/junction and protected paths before any staging operation.
3. **Exact candidate inventory:** Candidate keys match approved proposal paths exactly; no extra, missing or duplicate draft outputs. Only one-level `tests/fixtures/<safe-name>.py|.json|.txt|.md` is eligible for preview, even if the broader host scope permits other directories.
4. **Bounded UTF-8:** Up to 8 files, 8 KiB each, 32 KiB total, 200 lines each; no NUL/carriage return, bidi/invisible controls, surrogate code points or non-normalized Unicode. Raw content is not written to GitHub or durable logs by this function.
5. **Non-executing static checks:** `.json` is decoded as JSON with bounded input; `.py` is treated as plain text, **not AST-parsed/compiled/executed**; `.md/.txt` only pass byte/Unicode validation. No syntax/quality guarantee is claimed for Python.
6. **Disposable staging:** A new OS-managed `tempfile.TemporaryDirectory` is created. File creation uses `O_EXCL`, (O_NOFOLLOW) if supported, fsync and reread-to-verify. The directory is cleaned when the context exits. No existing repository, source checkout or user file is copied or modified.
7. **Sanitized receipts:** Return relative path, byte length, SHA-256, static check status and deterministic overall receipt digest, plus explicit `workspace_files_written=0`, `github_writes=0`, `commands_executed=0`, `model_code_executed=false`, `os_sandbox_verified=false`. Never return absolute staging path or raw candidate body.

## Data flow

```text
Trusted host supplies P00 task ID + WorkspaceScope
            |
Untrusted model DRAFT_ONLY plan + untrusted candidate text
            |
Independent host validator (scope + IDs + paths + sizes)
            |
OS-owned temporary fixture directory (not repo root)
            |
Exclusive-create files, hash, JSON/text check only
            |
Delete temporary directory and contents
            |
Sanitized SHA-256 receipt only
            |
NO source edits / NO shell / NO GitHub writes / NO model code execution
```

## Example for a trusted fixture test (NOT instructions to execute on user files)

```python
from pathlib import Path
from tools.fixture_draft_stager import preview_fixture_drafts
from tools.workspace_policy import WorkspaceScope

# root must be an already controlled, isolated test checkout;
# this example does not create or authorize the checkout.
scope = WorkspaceScope(Path("/trusted/test-checkout"), "P00", "phase/00-governance")
plan = {
    "schema_version": 1, "phase": "P00", "branch": "phase/00-governance",
    "task_id": "P00-T20", "summary": "Draft fixture review only",
    "file_proposals": [{
        "path": "tests/fixtures/candidate.json",
        "action": "DRAFT_ONLY", "reason": "Preview small JSON fixture"
    }],
    "checks": ["phase-policy"]
}
receipt = preview_fixture_drafts(
    plan, {"tests/fixtures/candidate.json": '{"ok":true}'},
    scope, expected_task_id="P00-T20"
)
# receipt contains hashes and status only; checkout and GitHub unchanged
```

Do not blindly use this path example; it must be an existing operator-trusted checkout with a host-provided scope. In particular, **do not use the user's real home directory, user chat history, storage vault or private model directory** as the staging root. The model never chooses the host path.

## Testing, warnings and limitations

`tests/test_fixture_draft_stager.py` tests actual temporary file creation/cleanup, deterministic receipts, no edits to a real fixture within controlled checkout, Python code containing `os.system` that is treated as text only, mismatched host task ID, disallowed operations, non-fixture paths, invalid JSON, oversized content, duplicate inventory, Unicode controls, nested traversal and symlink attempts. Both Linux governance suite and dedicated Windows staging tests are required. Do not hide a failed fixture test or weaken host scope to make CI green.

**Security boundary remains incomplete:** Python path checks have TOCTOU races in untrusted/shared directories. Temporary directory controls do not isolate the Python interpreter from the host. This code must never run arbitrary untrusted generated Python/JS, make source patches or invoke tests outside a validated OS sandbox. The full `P00-T19` OS isolation, file-handle broker, process/network limits, host authentication and `P00-T20` autonomous plan→patch→test→repair cycle remain explicitly blocked.

This operation does not deliver the app's persistent user files, chat backup, model download paths, design import/export, UI Help or release updates. Those product requirements remain in their previously designated phases.
