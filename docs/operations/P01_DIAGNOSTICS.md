# P01-T06 M18 native diagnostics foundation

**Status:** P01-T06 **DONE for the native diagnostic-spine task only**: Windows Rust unit tests, actual OS-local boot record, kernel-held writer lock, real sanitized panic-hook fixture and unsigned executable cold boot passed [Windows #44980027777](https://github.com/Vertex-Systems-Network/zynoa-2-local/actions/runs/44980027777) and [Governance #44980027876](https://github.com/Vertex-Systems-Network/zynoa-2-local/actions/runs/44980027876). The larger M18 diagnostics and auto-issue module is **NOT complete**. **Native startup/panic/IPC error-class capture now wired for verification.** The application remains unreleased; production diagnostics UI and end-user issue reporting are not implemented.

The native Rust API accepts only compile-time allowlisted module, severity and error code plus a numeric timestamp. It never receives free-form crash text, stack traces, file paths, secrets, prompts or user content. JSONL spool is append/sync-before-acknowledgement, capped at 1 MiB, 512 bytes per line and 128 distinct groups; counters are bounded and replay refuses corrupt files without resetting their contents. There is **no automatic issue publishing**, no cloud calls, and no WebView diagnostic command.

On app startup, Tauri's native OS path resolver selects the per-user local data root and enforces the configured `com.zynoa.desktop` directory identity. Rust creates only the `diagnostics` child of that location, refuses existing symlinked directories and invalid/corrupt log files, and records a `BootReady` event. A process-wide panic hook logs only the fixed `RuntimeFault` category (never the panic payload or stack); rejected IPC requests log only `IpcDenied`. Failure to initialize the diagnostic store aborts startup with a stable non-sensitive error code rather than pretending logging is active. GitHub-hosted Windows cold boot reads back only allowlisted fields; tests also exercise replay and corrupt-file preservation.

**Limitations and pending gates:** full M24 registry still owns later user-configurable paths and migrations. Race-safe open/creation, exclusive multi-process access, spool retention/rotation after the 1 MiB bound, end-user privacy preview, consent-gated reporting, production diagnostics UI, real visual screenshots and release signing are not yet implemented. No automatic issue publishing, cloud telemetry or frontend access to secrets is enabled. T06 must not be marked DONE without evaluating these gates.

Verification is GitHub-hosted Windows Rust cargo tests and desktop build, Python contracts, Governance v3.2 and task-board CI.

**Windows hardening (CI verified):** A Windows kernel-backed exclusive native writer guard prevents two app processes from writing the same JSONL spool; its empty lock file persists but the OS releases the handle on exit/crash. The second process fails with a sanitized startup code and cannot modify the active spool. A real unwind fixture checks that the panic payload never enters records. Linux/macOS multi-process exclusivity is **not** asserted. The UI now explicitly distinguishes native-only diagnostic metadata from absent workspace data and does not claim user logs are readable or remotely published.

**Unfinished product/release work:** full diagnostics/incident UI, user-facing privacy preview/consent, automatic issue relay, screenshot evidence, multi-platform locking/rotation, OS crash-dump capture, external security audit and production signing remain pending their respective P01 tasks/exit gates. Native panic capture is not a guarantee against process abort, power loss or OS-level termination. No claim of released or signed software is made.
