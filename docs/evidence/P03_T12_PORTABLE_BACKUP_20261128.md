Selected: Argon2id v1.3 (RustCrypto argon2 0.5.3, MIT/Apache-2.0), 64 MiB, three iterations, one lane, 32-byte output, 16-byte random salt, and AES-256-GCM (ring 0.17.14 already transitively locked, ISC/MIT/BSD mixed notices; use existing library, not new crypto). Per-archive 12-byte random nonce from ring SystemRandom; fixed authenticated version/length header and 128-bit tag. This is a standard AEAD alternative, not a claim of independent security certification. Reviewed official https://docs.rs/argon2/0.5.3/argon2/struct.Argon2.html , https://docs.rs/ring/0.17.14/ring/aead/ , https://docs.rs/ring/0.17.14/ring/rand/ , https://www.rfc-editor.org/rfc/rfc9106.html , https://docs.rs/crate/rusqlite/0.43.0/features and official registry metadata https://github.com/rust-lang/crates.io-index (argon2 0.5.3, blake2 0.10.6, base64ct 1.8.3 exact checksums non-yanked; existing digest 0.10.7 mac feature adds already locked subtle). Argon2 default features disabled, explicit zeroize and caller-owned wiped memory, no password-hash dependency. Local cargo unavailable, registry DNS unavailable in container: manually reconciled lock candidate must pass actual cargo --locked CI, RustSec and dependency review before acceptance. Alternatives: libsodium XChaCha20-Poly1305/Argon2id (additional native binary/build matrix), platform DPAPI/keychain-only encryption (not portable across machines), plaintext snapshots/hash-only (not authenticated encryption, rejected). No homegrown primitive.

Archive v1: fixed authenticated binary header, bounded uncompressed payload with versioned strict JSON manifest and consecutive binary items. Online SQLite Backup API to memory; serialize independently validated current V4 snapshot (no live WAL copy, no plaintext backup temp). Include existing vault records and all committed managed artifact bytes referenced by metadata; include published local conversation exports. Exclude keychain credentials, logs, runtime/model weights, caches, external paths, unlinked blobs/interrupted stages and previous backups. Validate size (64 MiB payload maximum), count, offsets, SHA-256, allowed logical IDs, duplicate paths and current schema. Restore only authenticated full archive into new app-private profile under backups/restored; read-only schema/FK/integrity and blob checks, verified marker last; never replace active profile, no auto-merge. Restore preview is plaintext; make this explicit and never expose absolute user paths/secret in logs. A failed/aborted staged restore is not marked verified. User may copy encrypted archive to independent disk and place a copied archive in fixed portable backup directory; no arbitrary renderer path authority. Existing app-local filesystem trust; no guarantee against a compromised same-user process, memory dumps or disk failure. Passphrase is never stored in product settings, logs, or receipts; native temporary buffers zeroized best effort, JS/SQLite/ring internal copies not guaranteed erased. Use explicit confirmation and fixed local destination; full M23 scheduling, external picker, retention, activation and selective merge are deferred.
