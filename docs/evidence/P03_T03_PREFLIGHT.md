## Existing boundary inspection and decision

- Native vault v2 implements postcommit conversation creation, message append and bounded ordinal history, but lacks conversation list/get and frontend service. Native app keeps vault under Mutex in lib.rs. The existing workspace handshake remains read-only and unchanged.
- Current build.rs AppManifest, generate_handler, main-readonly.json and tauri.conf.json explicitly grant only workspace_handshake; security.rs default-denies native capabilities. Existing P01/P02 tests assert the exact old command set. A new chat capability is a planned scoped M03 authority expansion, not a workspace write grant. Keep existing workspace ACL and negative tests, add separate explicitly named main-local chat capability, exact total command allowlist tests, runtime window check and native broker checks. Do not enable remote origin, arbitrary SQL, filesystem, process, network, credential, backup or assistant/tool injection commands. App CSP stays unchanged. Review old test assertions openly for authorized new command surface, retain all negative behavior.
- Official sources revalidated 2026-11-25: https://v2.tauri.app/security/capabilities/ (capabilities combine on same window; custom app commands must be explicitly restricted via AppManifest); https://v2.tauri.app/security/permissions/ ; https://v2.tauri.app/reference/acl/capability/ (local/remote scope); https://v2.tauri.app/develop/calling-rust/ (typed Serde invocation and native state); https://v2.tauri.app/develop/calling-frontend/ (events vs channels). Existing pinned Tauri/React/TypeScript/rusqlite licenses and versions from ADR-0030 retained, no new dependencies.
- Alternatives: direct frontend IndexedDB rejected (duplicates user data authority and bypasses v2 backup); generic database IPC rejected (arbitrary writes/reads and scope); sidecar HTTP service rejected for T03 (new process and network trust). Selected bounded typed native domain commands via existing Tauri IPC and state. Use ordinary React escaped text and native controls, no HTML/Markdown execution or localStorage. Compare separate Chat navigation to overloading Workbench: dedicated Chat view in existing workspace rail and allowlisted palette, retain Ctrl+1..6, F1 contextual help and responsive shell. Existing preferences/Help/Recovery remain unchanged.

## Tests-first implementation contract

| Command / control | Native/UX contract | Required verification |
|---|---|---|
| chat.list | Local main window only, stable bounded ID cursor and limit; title/revision/timestamps only, no content in list | Empty, paginated, repeated read, invalid limit/cursor, stable ordering |
| chat.create | Stable client request/entity ID, title 1..512 UTF-8 bytes; commit before reply; duplicate same ID and exact content reconciliation, conflicting duplicate rejected | Double-click, replay, wrong scope/window, DB rollback, reopen exact ID |
| chat.history | Explicit conversation ID, after ordinal, bounded count and bounded aggregate reply size; no cross-thread leakage | Empty, multi-page, missing ID, same-thread order, restart readback |
| chat.saveUserMessage | Native enforces role=user and terminal stored status, no caller-controlled role/status; stable message ID and same-thread parent; existing postcommit journal | Invalid, cross-thread, duplicate/retry, failed save, after restart; never claim model response |
| Chat view | Loading/empty/history/error/offline and disabled state, real create/select/refresh/load more and explicit save-only composer until inference exists; preserve draft on failure and reconcile uncertain writes | Accessible labels, keyboard focus, screen-reader status, browser preview never creates fake data, stale response suppressed |

Requests use schemaVersion=1, commandId, correlationId, scope=local, exact payload, deny unknown fields, bounded byte counts; errors fixed code and recovery text without content/paths or raw DB errors. Correlation and stable mutation IDs distinct. No privileged role/status supplied from renderer. Reads return verified version/command/correlation; no broadcast private content. Use bounded native calls without blocking UI (worker/thread where needed). Single mutation in flight; no optimistic persisted state; timeout is outcome unknown, refresh by stable ID before retry; never fabricate an assistant message. No delete, title edits, streaming, attachment, export, inference or backup controls represented as functional. UI cancellation prevents stale view updates, not a false claim of cancelled committed transaction.
