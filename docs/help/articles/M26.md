## What the user can expect

Open **Help → What's New** or **Settings → Changelog** to see released features, improvements, bug fixes and migration notes. For work that is not shipped, use the **In Progress / Known Issues** tab; it never implies a fix is installed. Release notes are version-scoped and available offline from last verified cache. Changelog information is not a substitute for actual release/update notification.

## How to navigate

1. Open What's New and choose a channel/version. Read version title and actual release date.
2. Filter by module, change type or search keywords. Open a change to see summary, linked issue/PR if publicly available and relevant Help article.
3. Select In Progress to track known bugs or planned enhancements without assuming resolution.
4. Select Version History for past releases, and Compare for version-to-version differences.
5. In Settings toggle changelog notifications or review unread versions.
6. Use `F1` for contextual Help; offline links open bundled version-matched local docs.

## Troubleshooting

- `CHG-E001`: release feed unavailable. Continue reading last verified cache and retry when online.
- `CHG-E002`: version not found for selected channel. Verify stable/beta selection.
- `CHG-E003`: invalid feed signature or manifest. Reject feed; preserve trusted cache; report sanitized diagnosis.
- `CHG-E004`: an issue or PR link is private/unavailable. Show local summary without exposing private metadata.
- `CHG-E005`: documentation link for installed version missing. Open bundled general Help and log issue.
- `CHG-E006`: user is offline. Present verified local snapshot with timestamp.
- `CHG-E007`: duplicate/contradictory events. Quarantine until reconciled rather than show double entries.
- `CHG-E008`: release docs mismatch. Block publication in CI; existing stable release unaffected.
- `CHG-E009`: changelog export path unavailable. Show save error and allow retry.
- `CHG-E010`: missing authorization for developer-only audit data. Do not expose private timeline.

**Privacy:** Do not share private prompts, project files, home paths, tokens or private issue details through public links. Support reporting follows the selected privacy/reporting mode.
