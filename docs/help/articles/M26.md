# M26 — What's New, Changelog & Change History (Help Draft)

**Implementation:** P02-T12 shared UI preview. Ten source-bound native candidates passed at `ffb5f0c`; final option and accessibility acceptance pending. **Screenshots:** preview candidates only. **Published GitHub Wiki:** pending verified deployment.

## Available in the P02 source preview

Open **System → Changelog**, or search Changelog in the command palette. Seven keyboard-accessible tabs: What’s New, Known Issues, Version History, Module Changes, Audit Timeline, Notifications and Migration Notes. Release and version views display actual no-verified-data states; Known Issues and Module Changes display bundled capability notices, not live GitHub issues or shipped changes. The three additional views explain the missing audit, preference and signed migration services; their disabled actions cannot execute. Search notices and filter by module; select a notice to read details; reset filters. Arrow keys/Home/End switch tabs, F1 opens contextual Help. A local runtime connection does not verify a release. No update, export, notification persistence or remote issue operation is enabled. The remainder below describes planned final functionality, not current availability.

Disabled release filters, fixed-problem history, issue/PR links, report action, audit detail/export, notification/unread controls and migration/recovery controls each show their prerequisites. They are not implemented backend features. Contextual guidance opens the bundled Help article. Original ten native preview candidates passed; final option and hosted Wiki evidence remain pending.

## What the user can expect (planned final module)

Open **Help → What's New** or **Settings → Changelog** to see released features, improvements, bug fixes and migration notes. For work that is not shipped, use the **In Progress / Known Issues** tab; it never implies a fix is installed. Release notes are version-scoped and available offline from last verified cache. Changelog information is not a substitute for actual release/update notification.

## How to navigate (planned final release workflow, not current P02)

1. Open What's New and choose a channel/version. Read version title and actual release date.
2. Filter by module, change type or search keywords. Open a change to see summary, linked issue/PR if publicly available and relevant Help article.
3. Select In Progress to track known bugs or planned enhancements without assuming resolution.
4. Select Version History for past releases, and Compare for version-to-version differences.
5. In Settings toggle changelog notifications or review unread versions.
6. Use `F1` for contextual Help; offline links open bundled version-matched local docs.

## Troubleshooting

- `CHG-E001`: release feed unavailable. Continue reading last verified cache and retry when online.
- `CHG-E002`: version not found for selected channel. Verify stable/beta selection.
- `CHG-E003`: invalid feed signature or manifest. Reject feed; preserve trusted cache; report sanitized diagnosis.
- `CHG-E004`: an issue or PR link is private/unavailable. Show local summary without exposing private metadata.
- `CHG-E005`: documentation link for installed version missing. Open bundled general Help and log issue.
- `CHG-E006`: user is offline. Present verified local snapshot with timestamp.
- `CHG-E007`: duplicate/contradictory events. Quarantine until reconciled rather than show double entries.
- `CHG-E008`: release docs mismatch. Block publication in CI; existing stable release unaffected.
- `CHG-E009`: changelog export path unavailable. Show save error and allow retry.
- `CHG-E010`: missing authorization for developer-only audit data. Do not expose private timeline.

**Privacy:** Do not share private prompts, project files, home paths, tokens or private issue details through public links. Support reporting follows the selected privacy/reporting mode.

## Developer CI incident publishing (internal P00 source; not a user feature)

The developer-only GitHub Actions incident reporter can attach a short, verified failing CI run link and Git commit SHA to a sanitized GitHub Issue, deduplicating same incidents and refusing unrelated/successful runs, PR code, secrets, local paths or private P0 incidents. It must run from trusted default branch with restricted `actions:read` and `issues:write`, not from untrusted PR code. Until PR #1 passes all premerge host security gates and is merged, **automatic issue reporting is inactive**; any manually created API issue proves only manual credentials, not CI delivery. This has no consumer UI/screenshot and is not a published M26 release. [Operator runbook](../../operations/P00_VERIFIED_CI_ISSUE_DELIVERY.md).
