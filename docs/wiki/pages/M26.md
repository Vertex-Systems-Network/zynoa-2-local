## Purpose

Explain released changes, version history, known issues and module-specific enhancements with evidence. New issues must be logged but **not** shown as fixed until implemented and published. Guides must follow version-matched UI behavior.

## Planned final user workflows (not current release features)

1. What's New > filter by category/version/module.
2. Known Issues > inspect open work without confusing it with release notes.
3. Change Detail > publicly accessible issue, merged PR, implementation notes and updated Help.
4. Version History > compare changes and review migrations.
5. Settings > notifications, unread release marker and sanitized export.
